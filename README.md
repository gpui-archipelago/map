# map

The **gpui fork map** viewer: a static React + Bun + Vite SPA that renders the
measured contract of the six crates.io GPUI forks (Changes, Alignment,
Configure, Journal) from the published `gocar.forkmap.v1` data family.

Source only — the data and the docs are fetched:

| What | Where it lives | How it gets here |
| --- | --- | --- |
| the export (`gocar.forkmap.*`: bundle, manifest, sidecars, buckets) | [`map-data`](https://github.com/gpui-archipelago/map-data) | `scripts/fetch-data.sh` → `web/forkmap/data/` |
| the study docs the reader links | [`gpui-corpus`](https://github.com/gpui-archipelago/gpui-corpus) `curation/research/` | `scripts/fetch-docs.sh` → `docs/04-user-docs/` |

`map-data` is generated by the published
[`cargo-gocar`](https://crates.io/crates/cargo-gocar) CLI from the measured
gpui contract dataset; this repo never runs the exporter.

## Layout

```
web/forkmap-spa/   the SPA (src, tests, smoke.py, vite.config.ts)
web/forkmap/data/  fetched bundle (gitignored)
docs/04-user-docs/ fetched study docs (gitignored)
scripts/           the two fetch scripts the CI also runs
```

The `web/forkmap/` layout is deliberate: the SPA fetches its data
document-relative as `forkmap/data/…` and the build mirrors the runtime-fetched
files into `dist/forkmap/data`, so the published artifact is self-contained.

## Develop

```bash
./scripts/fetch-data.sh          # or MAP_DATA_DIR=/path/to/map-data
./scripts/fetch-docs.sh          # or GPUI_CORPUS_DIR=/path/to/gpui-corpus
cd web/forkmap-spa
bun install
bun test                         # data-agnostic unit + render tests
bunx tsc --noEmit
bun run build                    # dist/, with the data + docs mirrors
python3 smoke.py                 # headless-Chrome proof of the built artifact
```

The tests assert the viewer's behaviour over whatever bundle is present — they
never pin corpus counts, digests or versions, so a data refresh cannot break
them. `smoke.py` takes `CHROME_BIN` if Chrome isn't `google-chrome-stable`.

## Publish

`.github/workflows/pages.yml` runs on push, on a weekly schedule (behind
`map-data`'s Monday export) and on manual dispatch: it fetches the data + docs,
runs `tsc`, `bun test`, the build and the smoke, then deploys `dist/` to GitHub
Pages. Pages must be enabled with **GitHub Actions** as the source.
